CHANGES SINCE PRE11

- HTTP requests with a disallowed Origin are rejected before RPC dispatch.
- Linux and Windows launchers bind HTTP and ZMQ RPC to loopback by default.
- Windows mining-reporter lifecycle and authentication handling are hardened.
- OpenAlias uses the Monzero oa1:xmz namespace; the live donation lookup is
  opt-in and no longer contacts inherited Monero donation infrastructure.
- Release package verification now enforces binary/source identity, archive
  safety, loopback launchers, and complete source manifests.
- The protected asset-ID fixed vector and release-hardening regressions were
  corrected and pass in the complete unit suite.
- Consensus identity, ports, address prefixes, supply rules, and the public
  asset hard-fork schedule remain unchanged from Genesis pre10 and pre11.

UPGRADE

Pre12 uses the same chain as pre10 and pre11. Stop wallets, miners, and the
daemon cleanly; verify the new archive checksum; and extract it into a new
directory. Existing blockchain and wallet data do not require migration. Keep
the previous verified binaries until the updated client has synchronized and
remained healthy. Never reuse a Monero or other CryptoNote seed with Monzero.

TEST STATUS AND LIMITATIONS

All 1,303 unit tests passed. Focused DNS/OpenAlias, HTTP Origin, asset, and RPC
regressions passed, and the asset-wire sanitizer fuzz target completed 10,000
executions without a finding. All five archives pass their checksums and
non-production package verifiers. The source packager produced three
byte-for-byte identical local archives. The exact Linux package starts and
stops successfully in the pinned, network-disabled Ubuntu compatibility
container and requires at most GLIBC 2.29.

Native Windows CLI/GUI execution, independently operated binary reproduction,
release signing, and an independent security review remain outstanding.
Windows may show an unknown-publisher warning. Local deterministic packaging
is not represented as independent reproduction.
